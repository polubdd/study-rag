# study-rag

Сервис для подготовки к сессии по своим конспектам. Загружаешь конспекты, задаёшь вопросы и получаешь ответы со ссылками на конкретный раздел. Из тех же конспектов автоматически собираются карточки для интервального повторения и квиз.

```
Вопрос: чем PCA связан с собственными векторами?

Собственный вектор v матрицы A — ненулевой вектор, для которого Av = λv. [1]
На этом держится PCA: ковариационная матрица симметрична. [1]
                                                     дословно из конспекта
[1] Линейная алгебра / Собственные значения · linal
```

Работает без LLM и без интернета. Если подключить модель (локальную через Ollama или облачную), ответы становятся связным текстом, но каждое утверждение всё равно должно ссылаться на конспект.

## Что умеет

- **Курсы и материалы.** Конспекты в `.md` (Obsidian), `.txt`, `.docx` (Word, Google Docs) и `.pdf`. Заголовки берутся из стилей Word или угадываются в простом тексте. Повторно загруженный файл узнаётся по хешу.
- **Вопросы.** Гибридный поиск и ответ со ссылками. На вопрос не по теме сервис честно отвечает «В конспектах этого нет», а не выдаёт уверенный ответ из случайного раздела.
- **Карточки.** Из определений («Ранг — …»), формулировок («Закон больших чисел: …») и формул под заголовками. Повторение по SM-2, тому же алгоритму, что в Anki: «не помню» — через 10 минут, «хорошо» — через 1, 3, 7… дней. Повторная генерация не сбрасывает прогресс.
- **Квиз.** Определение с пропуском и четыре варианта. Неправильные варианты берутся из того же курса и того же вида карточек, чтобы было не слишком легко.
- **Синонимы курса.** Свой словарь вида «матожидание, среднее, E[X]» поверх общего RU/EN-словаря.

## Как устроено

```
файл ─► markdown ─► фрагменты по заголовкам ─► SQLite
                                               │
вопрос ─► + синонимы ─► BM25 ─┐                │
                     TF-IDF ──┼─ RRF ─► топ-4 ─┼─► «есть ли это в конспектах?»
              [эмбеддинги] ───┘                │      └─► ответ: экстрактивный | LLM + проверка ссылок
                                               └─► карточки ─► SM-2 / квиз
```

### Решения, которые пришлось принять

**Поиск: три метода и слияние по рангам.** BM25 по стемам точно находит термины. TF-IDF по символьным n-граммам переживает опечатки и словоформы, которые грубый стеммер не свёл. Эмбеддинги (если подключены) понимают перефразировки. Результаты объединяются через Reciprocal Rank Fusion: у методов разные шкалы скоров, а ранги сравнимы.

**Синонимы дали больше, чем смена алгоритма.** Я измерил качество поиска на вопросах, сформулированных своими словами («модель запомнила трейн, а на тесте плохо» вместо «переобучение»). Оказалось, что гибрид сам по себе почти ничего не добавляет к символьному TF-IDF. Промахи были не про алгоритм, а про язык: в конспекте «Recall», а в вопросе «полнота». Добавил общий словарь RU/EN для математики и ML. Чтобы не подогнать словарь под тест, после него написал **отложенный** набор вопросов:

| | recall@1 | recall@3 | MRR |
|---|:---:|:---:|:---:|
| BM25 | 0.70 | 0.75 | 0.74 |
| символьный TF-IDF | 0.70 | 0.80 | 0.75 |
| гибрид (RRF) | 0.70 | 0.75 | 0.74 |
| **гибрид + синонимы** | **0.90** | **0.90** | **0.91** |

*Отложенный набор: 20 вопросов, 26 фрагментов. Повторить: `python -m rag.evaluate -v`.*

Оставшиеся промахи («ленивые вычисления» → генераторы) — это уже смысловые синонимы, их закрывают эмбеддинги.

**Экстрактивный ответ — жадный выбор по покрытию вопроса.** Первая версия брала предложения с лучшим совпадением. На «чем PCA связан с собственными векторами» она выдавала два определения собственного вектора, а предложение про PCA проигрывало, хотя только оно и отвечает на вопрос. Теперь каждое следующее предложение берётся за *новые* слова вопроса, которые ещё не покрыты.

**LLM не может отвечать без ссылок.** Модель обязана ставить `[n]` после каждого утверждения. Ответ без ссылок или со ссылкой на несуществующий фрагмент отбрасывается, и показывается экстрактивный, с пометкой почему.

**«В конспектах этого нет».** Поиск всегда что-то возвращает, поэтому отдельно проверяется, покрыты ли слова вопроса корпусом (сами или через синоним) и насколько силён лучший фрагмент. Без этой проверки на «как приготовить борщ» сервис уверенно цитировал SVD.

**Карточки: отличить понятие от связки.** «Закон больших чисел: …» — понятие, а «На этом держится PCA: …» и «Обратное неверно: …» — нет. Понятием считается именная группа без служебных слов и глаголов, где глагол определяется по окончанию.

**SQLite, а не векторная база.** Конспекты одного студента — это тысячи фрагментов. Индекс в памяти строится за доли секунды и пересобирается, только когда меняется курс. Вся база — один файл.

## Запуск

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload     # http://localhost:8000, при первом запуске создаётся демо-курс
python -m pytest                  # 27 тестов
python -m rag.evaluate -v         # качество поиска
```

С LLM (любой OpenAI-совместимый API):

```bash
export LLM_BASE_URL=http://localhost:11434/v1   # Ollama
export LLM_MODEL=qwen2.5:7b
export EMBED_MODEL=bge-m3                         # необязательно: добавит векторный поиск
```

С LLM к карточкам добавляются вопросы на понимание («почему нельзя KFold на временных рядах»).

## API

| | |
|---|---|
| `GET/POST /api/courses`, `DELETE /api/courses/{id}` | курсы |
| `POST /api/courses/{id}/documents` | загрузка файлов (multipart, несколько сразу) |
| `POST /api/courses/{id}/ask` | вопрос → ответ со ссылками |
| `GET /api/courses/{id}/search?q=` | поиск фрагментов |
| `GET /api/courses/{id}/cards?due=true`, `POST /api/cards/{id}/review` | повторение |
| `GET /api/courses/{id}/quiz` | квиз |
| `GET/PUT /api/courses/{id}/synonyms` | синонимы курса |

## Ограничения

- Стеммер самодельный и грубый. pymorphy3 дал бы точнее, но тянет словари на 20 МБ.
- PDF читается только с текстовым слоем: сканы лекций нужно сначала прогнать через OCR.
- Формулы из PDF теряют вёрстку (дроби, индексы).
- Один пользователь: нет авторизации, база лежит локально.
