# study-rag

Задаёшь вопрос по своим конспектам и получаешь ответ со ссылками на разделы, откуда он взят. Сделал для подготовки к сессии.

```
$ python -m rag.cli "чем PCA связан с собственными векторами"

Источники:
[1] linal › Линейная алгебра / Собственные значения  (score 9.85)
    ...собственные векторы для разных λ ортогональны. На этом держится PCA...
```

## Как устроено

```
notes/*.md → нарезка по заголовкам → BM25 → top-k фрагментов → [LLM] → ответ с [1], [2]
```

- **Нарезка по заголовкам, а не по N символам.** Иначе определение рвётся посередине. У каждого фрагмента сохраняется путь `Линал / Матрицы / Ранг`, и он участвует в поиске: часто термин есть только в заголовке.
- **BM25 написан руками**, без библиотеки: хотелось разобраться, откуда берётся скор. Чтобы «матрицы», «матрицей» и «матрицу» считались одним словом, добавил грубый стеммер по русским окончаниям.
- **LLM необязательна.** Без неё выводятся найденные фрагменты. С ней модель отвечает *только* по фрагментам и ставит номер источника после каждого утверждения. Так проще поймать галлюцинацию: открываешь [2] и проверяешь.

## Запуск

```bash
pip install pytest
python -m rag.cli "как найти обратную матрицу"
python -m pytest
```

С локальной моделью через [Ollama](https://ollama.com):

```bash
ollama pull qwen2.5:7b
export LLM_BASE_URL=http://localhost:11434/v1
python -m rag.cli "что говорит ЦПТ"
```

Подойдёт любой OpenAI-совместимый API: `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`.

## Что дальше

- Гибридный поиск: BM25 + эмбеддинги. BM25 не находит синонимы: «обращение матрицы» ≠ «обратная матрица».
- Нормальная лемматизация (pymorphy3) вместо самодельного стеммера.
- Загрузка PDF с лекциями, а не только markdown.
- Набор вопросов с правильными разделами, чтобы мерить качество поиска (recall@k), а не проверять глазами.
